# Menu-Bar Tray Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS menu-bar menu listing the fleet with per-VM quick actions (connect VNC/SSH, copy IP, restart, suspend/resume, stop, delete), plus close→hide so the app lives in the menu bar (plan 3 of 3).

**Architecture:** Rust owns the tray. A background poll loop hits `GET /vms` (Rust already holds the ephemeral port + per-run token via `ApiConfig`), projects each VM to a 3-field `TrayVm`, and rebuilds the native menu only when the projection changes. Lifecycle and connect actions execute directly in Rust over HTTP / `open(1)`; only items that surface the window (Show, Settings, Doctor, New, Suspend-all) emit a `tray-action` event the webview handles. This is deliberately **not** frontend-push: the webview's fleet SSE is route-scoped and paused when hidden, so it is dead exactly when the tray needs data.

**Tech Stack:** Rust (Tauri 2, `reqwest` blocking, `tauri-plugin-dialog`, `tauri-plugin-clipboard-manager`), Vue 3 + Pinia for the one webview-side listener.

Spec: `docs/superpowers/specs/2026-07-14-settings-doctor-and-tray-menu-design.md` (see §6, revised 2026-07-16, for why Rust-driven)
Depends on: plans 1 and 2 (both **merged**) — the engine endpoints and the Settings/Doctor routes exist and are live.

## Global Constraints

- **This is macOS-only.** The app requires Apple silicon; `open(1)`, `pbcopy`, and the tray are all macOS. Do not add cross-platform branches.
- **Match the existing `lib.rs` style.** Background work is a `std::thread::spawn` with values captured by `move` (mirror the readiness-probe thread at `lib.rs:~190`). Comments explain *why*, not *what*, and are dense (read the existing ones).
- **The engine wire contract is stable and shared** (CLI + MCP + desktop). `GET /vms` returns `[{name, state, source, healthy, …}]` where `name` is the full `mf-*` form, `state` ∈ `running|stopped|suspended`, `healthy` is a bool. `GET /vms/{name}/connection` returns `{ip, ssh, vnc, guest_server, exec}`. Every request needs header `X-Macfleet-Token: <token>`.
- **Menu mutation must happen on the main thread** on macOS. A background thread computes the projection; when it changes, it calls `app_handle.run_on_main_thread(move || { … })` to rebuild.
- **Rebuild only on change.** Rebuilding a native menu on every poll can flicker or dismiss an open menu. `TrayVm` derives `PartialEq`; compare the whole `Vec<TrayVm>`.
- **Menu IDs encode `vm:<name>:<action>`.** VM names match `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` — no colons — so the encoding is unambiguous. Global IDs are bare words (`new`, `suspend-all`, `settings`, `doctor`, `show`, `quit`).
- `mf-golden` is filtered out of the fleet by the engine's `list_vms` already; the tray shows what `/vms` returns, so no golden handling is needed here.
- Rust: `cargo test` (from `desktop/`, via `make rust-test`), `cargo clippy -- -D warnings` (`make rust-lint`, the crate is pedantic-clean), `cargo fmt` (`make rust-format`).
- Frontend: `bun run test:unit`, `bun run build`, `make lint-desktop`. Coverage gates lines 95 / branches 90 / functions 85 / statements 92 — NOT 100.
- **Do not modify `desktop/src-tauri/tauri.conf.json`** — an earlier subagent parked a `devUrl` hack there; it was reverted. To reach a route for a live check, navigate in-app.
- **Do NOT run `make ci`** — it pulls a rust-coverage target needing `cargo-llvm-cov`, not installed here.
- Conventional Commits. No `Co-authored-by`. `git add` only the files each task names.
- **Tauri 2 plugin APIs drift between minor versions.** Where a snippet calls a plugin (dialog, clipboard, menu builders), it is written against the idiomatic 2.x API. If the installed crate's signature differs, adapt it — the shape is the spec, the exact method name is not. Say so in your report when you adapt one.

```rust
use serde::Deserialize;

/// One VM as the tray needs it — three fields, not the whole engine `Vm`. Deserialized from
/// `GET /vms`; extra JSON fields (source, cpu, memory_mb, lease_expires_at…) are ignored.
#[derive(Clone, PartialEq, Eq, Deserialize)]
pub struct TrayVm {
    pub name: String,
    pub state: String,
    pub healthy: bool,
}

/// Status glyph. `◐` is "running but the guest health check hasn't passed yet" (booting);
/// suspended and stopped both read as `○` — neither is reachable, and the submenu differs by
/// offering Resume vs the running actions.
pub fn dot(vm: &TrayVm) -> &'static str {
    match (vm.state.as_str(), vm.healthy) {
        ("running", true) => "●",
        ("running", false) => "◐",
        _ => "○",
    }
}

pub fn short(name: &str) -> &str {
    name.strip_prefix("mf-").unwrap_or(name)
}

/// Stable display order so the menu doesn't reshuffle between rebuilds.
pub fn project(mut vms: Vec<TrayVm>) -> Vec<TrayVm> {
    vms.sort_by(|a, b| a.name.cmp(&b.name));
    vms
}

#[derive(Debug)]
pub enum Action {
    Vm { name: String, verb: String },
    Global(String),
}

/// Menu ID for a per-VM action. `name` is the SHORT name (what the engine's URL layer accepts
/// either way); it cannot contain a colon (see the name charset), so `vm:<name>:<verb>` parses
/// unambiguously.
pub fn vm_id(name: &str, verb: &str) -> String {
    format!("vm:{name}:{verb}")
}

pub fn parse_id(id: &str) -> Option<Action> {
    if let Some(rest) = id.strip_prefix("vm:") {
        let (name, verb) = rest.split_once(':')?;
        if name.is_empty() || verb.is_empty() {
            return None;
        }
        return Some(Action::Vm { name: name.to_string(), verb: verb.to_string() });
    }
    if id.is_empty() {
        return None;
    }
    Some(Action::Global(id.to_string()))
}
```

```rust
use std::time::Duration;

/// Authenticated blocking client for the local engine, used from the tray's background
/// threads (never the UI thread). Blocking + a short timeout keeps each call self-contained:
/// a wedged engine can't pin a UI thread, and a poll that stalls just skips a cycle.
pub struct Engine {
    base: String,
    token: String,
    client: reqwest::blocking::Client,
}

fn url(base: &str, path: &str) -> String {
    format!("{base}{path}")
}

impl Engine {
    pub fn new(port: u16, token: &str) -> Engine {
        Engine {
            base: format!("http://127.0.0.1:{port}"),
            token: token.to_string(),
            client: reqwest::blocking::Client::builder()
                .timeout(Duration::from_secs(8))
                .build()
                .unwrap_or_default(),
        }
    }

    pub fn list_vms(&self) -> Result<Vec<TrayVm>, String> {
        self.client
            .get(url(&self.base, "/vms"))
            .header("X-Macfleet-Token", &self.token)
            .send()
            .and_then(reqwest::blocking::Response::error_for_status)
            .map_err(|e| e.to_string())?
            .json::<Vec<TrayVm>>()
            .map_err(|e| e.to_string())
    }

    /// Fire a lifecycle POST (restart/suspend/resume/down/nuke). No body; the engine takes the
    /// VM name from the path. Returns Err on any non-2xx so the caller can toast.
    pub fn post(&self, path: &str) -> Result<(), String> {
        self.client
            .post(url(&self.base, path))
            .header("X-Macfleet-Token", &self.token)
            .send()
            .and_then(reqwest::blocking::Response::error_for_status)
            .map(|_| ())
            .map_err(|e| e.to_string())
    }

    pub fn connection_ip(&self, short_name: &str) -> Result<String, String> {
        #[derive(Deserialize)]
        struct Conn {
            ip: String,
        }
        let conn = self
            .client
            .get(url(&self.base, &format!("/vms/{short_name}/connection")))
            .header("X-Macfleet-Token", &self.token)
            .send()
            .and_then(reqwest::blocking::Response::error_for_status)
            .map_err(|e| e.to_string())?
            .json::<Conn>()
            .map_err(|e| e.to_string())?;
        if conn.ip.is_empty() || conn.ip == "—" {
            return Err("VM has no IP yet".into());
        }
        Ok(conn.ip)
    }
}
```

```rust
use tauri::menu::{Menu, MenuItem, PredefinedMenuItem, Submenu};

/// Build the whole tray menu for the current fleet. Per-VM submenus first, then the globals,
/// then Show/Quit. Called on the main thread only (menu objects aren't Send on macOS).
pub fn build_menu(app: &tauri::AppHandle, vms: &[TrayVm]) -> tauri::Result<Menu<tauri::Wry>> {
    let menu = Menu::new(app)?;

    for vm in vms {
        let name = short(&vm.name).to_string();
        let label = format!("{} {}", dot(vm), name);
        let running = vm.state == "running";
        let sub = Submenu::with_id(app, vm_id(&name, "sub"), label, true)?;
        if running {
            let can = vm.healthy; // connect/copy only make sense once the guest is up
            sub.append(&MenuItem::with_id(app, vm_id(&name, "vnc"), "Connect VNC", can, None::<&str>)?)?;
            sub.append(&MenuItem::with_id(app, vm_id(&name, "ssh"), "Connect SSH", can, None::<&str>)?)?;
            sub.append(&MenuItem::with_id(app, vm_id(&name, "ip"), "Copy IP address", can, None::<&str>)?)?;
            sub.append(&PredefinedMenuItem::separator(app)?)?;
            sub.append(&MenuItem::with_id(app, vm_id(&name, "restart"), "Restart", true, None::<&str>)?)?;
            sub.append(&MenuItem::with_id(app, vm_id(&name, "suspend"), "Suspend", true, None::<&str>)?)?;
            sub.append(&MenuItem::with_id(app, vm_id(&name, "down"), "Stop", true, None::<&str>)?)?;
        } else {
            sub.append(&MenuItem::with_id(app, vm_id(&name, "resume"), "Resume", true, None::<&str>)?)?;
        }
        sub.append(&PredefinedMenuItem::separator(app)?)?;
        sub.append(&MenuItem::with_id(app, vm_id(&name, "show"), "Show in app", true, None::<&str>)?)?;
        sub.append(&MenuItem::with_id(app, vm_id(&name, "delete"), "Delete…", true, None::<&str>)?)?;
        menu.append(&sub)?;
    }

    if !vms.is_empty() {
        menu.append(&PredefinedMenuItem::separator(app)?)?;
    }
    menu.append(&MenuItem::with_id(app, "new", "New VM", true, None::<&str>)?)?;
    menu.append(&MenuItem::with_id(app, "suspend-all", "Suspend all", true, None::<&str>)?)?;
    menu.append(&PredefinedMenuItem::separator(app)?)?;
    menu.append(&MenuItem::with_id(app, "settings", "Settings…", true, None::<&str>)?)?;
    menu.append(&MenuItem::with_id(app, "doctor", "Doctor…", true, None::<&str>)?)?;
    menu.append(&PredefinedMenuItem::separator(app)?)?;
    menu.append(&MenuItem::with_id(app, "show", "Show macfleet", true, None::<&str>)?)?;
    menu.append(&MenuItem::with_id(app, "quit", "Quit", true, None::<&str>)?)?;
    Ok(menu)
}
```

- [ ] **Step 3: Write the poll loop**

Add to `tray.rs`:

```rust
use std::time::Duration as StdDuration;

/// Background poll: fetch `/vms`, project, and rebuild the tray menu only when the projection
/// changes. Runs off the UI thread (blocking HTTP); menu rebuilds hop to the main thread via
/// run_on_main_thread because macOS menu objects aren't Send. A failed poll (engine still
/// booting, transient error) just skips a cycle and retries — the tray keeps its last good menu.
pub fn spawn_poll(app: tauri::AppHandle, port: u16, token: String) {
    std::thread::spawn(move || {
        let engine = Engine::new(port, &token);
        let mut last: Option<Vec<TrayVm>> = None;
        loop {
            if let Ok(vms) = engine.list_vms() {
                let projected = project(vms);
                if last.as_ref() != Some(&projected) {
                    let app2 = app.clone();
                    let for_menu = projected.clone();
                    let _ = app.run_on_main_thread(move || {
                        if let (Some(tray), Ok(menu)) =
                            (app2.tray_by_id("main"), build_menu(&app2, &for_menu))
                        {
                            let _ = tray.set_menu(Some(menu));
                        }
                    });
                    last = Some(projected);
                }
            }
            std::thread::sleep(StdDuration::from_secs(2));
        }
    });
}
```

```rust
use tauri_plugin_dialog::{DialogExt, MessageDialogButtons, MessageDialogKind};

/// Tray click dispatch. Runs on the main thread (Tauri calls it there). Anything that does
/// blocking I/O (HTTP, a confirm dialog) is pushed to a worker thread so the menu closes
/// immediately and the UI thread never stalls. Engine access needs the per-run config, read
/// from managed state.
pub fn on_menu_event(app: &tauri::AppHandle, id: &str) {
    let Some(action) = parse_id(id) else { return };
    match action {
        Action::Global(g) => on_global(app, &g),
        Action::Vm { name, verb } => on_vm(app, &name, &verb),
    }
}

fn engine_from(app: &tauri::AppHandle) -> Option<Engine> {
    let cfg = app.try_state::<crate::state::ApiConfig>()?;
    Some(Engine::new(cfg.port, &cfg.token))
}

fn on_vm(app: &tauri::AppHandle, name: &str, verb: &str) {
    match verb {
        "restart" | "suspend" | "resume" | "down" => {
            let (Some(engine), name, verb) = (engine_from(app), name.to_string(), verb.to_string())
            else {
                return;
            };
            let path = format!("/vms/{name}/{verb}");
            std::thread::spawn(move || {
                if let Err(e) = engine.post(&path) {
                    log::warn!("tray {verb} {name} failed: {e}");
                }
            });
        }
        "delete" => confirm_and_delete(app, name),
        // vnc/ssh/ip land in Task 5; show lands in Task 6.
        _ => {}
    }
}

fn confirm_and_delete(app: &tauri::AppHandle, name: &str) {
    let (Some(engine), app2, name) = (engine_from(app), app.clone(), name.to_string()) else {
        return;
    };
    std::thread::spawn(move || {
        // Native two-button confirm — the app's in-UI two-step arm can't be expressed in a
        // native menu, so a modal is the equivalent guard against a stray click.
        let ok = app2
            .dialog()
            .message(format!("Delete {name}? This stops and removes the VM. It cannot be undone."))
            .title("macfleet")
            .kind(MessageDialogKind::Warning)
            .buttons(MessageDialogButtons::OkCancelCustom("Delete".into(), "Cancel".into()))
            .blocking_show();
        if ok {
            if let Err(e) = engine.post(&format!("/vms/{name}/nuke")) {
                log::warn!("tray delete {name} failed: {e}");
            }
        }
    });
}

fn on_global(app: &tauri::AppHandle, g: &str) {
    match g {
        "show" => {
            if let Some(w) = app.get_webview_window("main") {
                let _ = w.show();
                let _ = w.set_focus();
            }
        }
        "quit" => app.exit(0),
        // new / suspend-all / settings / doctor land in Task 6.
        _ => {}
    }
}
```

If the installed `tauri-plugin-dialog` differs (e.g. `OkCancel` without custom labels, or a different return), adapt to produce the same "confirm before nuke" behaviour and note it in your report. The delete MUST be gated — do not ship an unconfirmed nuke.

```rust
/// VNC/SSH hand off to macOS via `open(1)` — no tauri-plugin-opener scope needed (opener only
/// permits http/https/mailto/tel by default; shelling out sidesteps that). Copy IP writes to
/// the clipboard. All three already have the IP resolved.
fn connect(app: &tauri::AppHandle, verb: &str, ip: &str) {
    match verb {
        "vnc" => {
            let _ = std::process::Command::new("open").arg(format!("vnc://admin@{ip}")).spawn();
        }
        "ssh" => {
            let _ = std::process::Command::new("open").arg(format!("ssh://admin@{ip}")).spawn();
        }
        "ip" => {
            use tauri_plugin_clipboard_manager::ClipboardExt;
            if let Err(e) = app.clipboard().write_text(ip.to_string()) {
                log::warn!("tray copy ip failed: {e}");
            }
        }
        _ => {}
    }
}
```

**Notes:** `admin` is the guest user (`GUEST_USER` in the engine). The `open ssh://` scheme opens the user's default SSH handler (Terminal by default on macOS). `tauri-plugin-clipboard-manager`'s Rust `ClipboardExt::write_text` is the idiomatic 2.x call — adapt if the installed version differs, and note it.

- [ ] **Step 4: Write the composable**

Create `desktop/src/composables/useTrayMenu.ts`:

```ts
import { onUnmounted } from 'vue'
import { useRouter } from 'vue-router'
import { useFleet } from '../stores/fleet'
import { useSettings } from '../stores/settings'
import { useUi } from '../stores/ui'

interface TrayAction {
  action: string
  vm?: string
}

const short = (n: string): string => (n.startsWith('mf-') ? n.slice(3) : n)

/** Handles the `tray-action` events Rust emits for menu items that surface the window
 * (Settings/Doctor/New/Suspend-all/Show). Lifecycle and connect actions execute in Rust and
 * never reach here. Mounted once at app scope (DefaultLayout), so it lives as long as the app. */
export function useTrayMenu(): void {
  const router = useRouter()
  const fleet = useFleet()
  const ui = useUi()
  const settings = useSettings()

  async function dispatch(a: TrayAction): Promise<void> {
    switch (a.action) {
      case 'settings':
        await router.push('/settings')
        break
      case 'doctor':
        await router.push('/settings')
        void settings.runDoctor()
        break
      case 'new':
        void fleet.create()
        break
      case 'show':
        if (a.vm) ui.selectVm(a.vm)
        break
      case 'suspend-all':
        for (const v of fleet.vms) {
          if (v.state === 'running') void fleet.suspend(short(v.name))
        }
        break
    }
  }

  // Dynamic import: `@tauri-apps/api/event` is absent under vitest/vite-dev outside Tauri.
  // The mock in the test intercepts this; in a plain browser the catch keeps it inert.
  let unlisten: (() => void) | null = null
  import('@tauri-apps/api/event')
    .then(({ listen }) =>
      listen<TrayAction>('tray-action', (e) => {
        void dispatch(e.payload)
      }),
    )
    .then((un) => {
      unlisten = un
    })
    .catch(() => {})

  onUnmounted(() => unlisten?.())
}
```

`vi.mock('@tauri-apps/api/event', …)` intercepts the composable's dynamic `import()` (the factory applies to both static and dynamic imports). The test drains it with `flushPromises()` before invoking `handler`. Note `useTrayMenu()` calls `onUnmounted` outside a component here, which Vue warns about but does not fail on — harmless in the test; in production it is called from `DefaultLayout`'s setup where the hook is valid. Report any adjustment you make.

```rust
        .on_window_event(|window, event| {
            // Menu-bar app: closing the window hides it and leaves the app (and its tray)
            // running. Quit is the only path that actually exits — via the tray's "Quit", ⌘Q,

            if let tauri::WindowEvent::CloseRequested { api, .. } = event {
                api.prevent_close();
                let _ = window.hide();
            }
        })
```

The tray is not unit-testable end to end — its logic core (Task 1) and the webview dispatch (Task 6) are, but the native menu, the poll loop, the HTTP actions, and close→hide are only real when driven live.
